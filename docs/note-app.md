# 新人向けアプリ（第1段階）の作り

2026年11月17日。CLAUDE.md の方針（新人向けの学習アプリ）にそって作ったものの記録です。

## 1. 置き場所
1. `apps/note/` が新人向けアプリと管理者ページ（Vite と TypeScript）。公開先は Firebase Hosting の `/note/`。管理者ページは `/note/#admin`。
2. `apps/note/config/` が設定ファイル。コードを触らずに変えられる。
   1. `skeleton.json`：部署6つ、見出し6つ、見出しごとの「何を書けばいいか」の例（部署ごと）。
   2. `limits.json`：1人1日のAI 30回、写真 20枚、写真の大きさ。
   3. `ai.json`：AIのモデル（claude-haiku-5-5）、費用の目安を出す単価と為替、月の予算の目安。単価は目安なので、料金表で確かめて直す。
   4. `copy.json`：画面の文言。同意の文と版（version）、書いてはいけないこと、上限のお知らせ、利用規約とプライバシーポリシー（準備中の文。ここで差し替える）。同意の版を変えると、全員にもう一度同意を取る。
   5. `events.json`：計測するイベントの種類。足すときは `firebase/firestore.rules` も直す。
3. `firebase/functions-note/` がサーバー側（TypeScript）。`npm run build` で、apps/note の共通の処理と設定を `src/shared`、`src/config` に写してから組み立てる。写したものは手で直さない。
4. 旅館向けアプリ（`src/app.html`、`firebase/functions/`）とは、コードを分けている。Firebase のプロジェクト、読み書きの決まり（firestore.rules）、公開の手順は同じ。

## 2. データ
| 場所 | 中身 | 読み書きできる人 |
|---|---|---|
| `users/{uid}` | 同意（文、版、利用規約の版、日時）、来た場所（utm）、今の職場と部署、職場の履歴、紐づけ済みか | 本人。運営者は読むだけ。名前とメールは入れない |
| `users/{uid}/notes/{id}` | 職場、部署、見出し、題、もとの文、手順、写真の場所、AIを使ったか、AIの結果を直したか、言葉の印 | 本人だけ。運営者も直接は読めない |
| `users/{uid}/cards/{id}` | 表、裏、種類、見出し、覚えた・まだ、練習の回数 | 本人だけ |
| `users/{uid}/slots/{id}` | 写真を送ってよい枠 | サーバーだけ |
| `users/{uid}/photos/{id}`（Storage） | 写真（スマホの中で長い辺1280pxに縮める） | 本人だけ。枠があるときだけ送れる |
| `workplaces/{id}` | 宿の名前、温泉地か市町村、見分けるための鍵（norm）、まとめ先、導入済み | だれでも読める。足すのはサーバー。まとめると導入済みは運営者 |
| `events/{id}` | 利用者ID、種類、日時、職場、部署、端末 | 本人が足すだけ。読めるのは運営者 |
| `usage/{uid}_{日付}` | AIと写真の回数、トークン数 | サーバーだけ |
| `stats/summary`、`stats/workplaces`、`stats/users` | 夜に作る集計 | 運営者だけが読む |
| `auditLogs/{id}` | 運営者がメモの中身を見た記録 | サーバーが書き、運営者が読む |

## 3. 決めたこと
1. 継続の数え方（圭佑と決めた）：「2週間後も使っている」は、登録から14〜20日目にメモを1件以上「書いた」（新しく保存した、または直して保存した）人の割合。管理者ページには「開いただけ」の数も参考に出す。1日後は1〜2日目、3日後は3〜6日目、1週間後は7〜13日目、4週間後は28〜34日目。
2. 1人あたりの週のメモ：直近7日に開いた人の、メモの保存の平均。
3. 利用者が3人以上の職場：直近30日に開いた人が3人以上いる職場。管理者ページでは「提案候補」。
4. 職場の見分け方：名前の表記をそろえ（全角半角、カタカナとひらがな、空白、「旅館」「ホテル」「温泉」など）、名前に入っている温泉地や市町村の名前を外した鍵（`placeKey`）で比べる。似た名前があれば、足す前に「この宿ではありませんか」と聞く。
5. 書いてはいけないもの：保存の前に、スマホの中で探す（「〇〇様」、同じ行の部屋番号、電話番号、メール、暗証番号や金庫の番号）。AIが使えるときは、AIが見つけたものも合わせる。見つけたら「消しますか」と聞く。
6. AIが答えない話題：アレルギー、けが、体調、お金、お客様とのトラブル、ハラスメント、災害。スマホの中で先に止め、サーバーでも止める。止めたときは、回数に数えない。
7. 上限：1人1日（日本時間0時に戻る）AI 30回、写真 20枚。職場が導入済みなら上限なし。職場を移ったら、移った先の状態に合わせる。上限のお知らせは、画面の下に小さく、閉じられる形で、1日1回だけ。
8. PDF：スマホの中で作る。文字をスマホの字で絵として描き、ページに並べる（どのスマホでも字が崩れないため。そのかわり、PDFの中の文字は選べない）。写真はPDFに入れていない。
9. 運営者は、メモの中身を直接は読めない。管理者ページの「メモの中身を開く」はサーバーの関数を通し、だれがいつ、だれのメモを見たかを必ず残す。
10. 新人向けアプリの運営者は、旅館向けアプリと同じ運営者（`OPERATOR_EMAIL`）。管理者ページのログインは、メールのリンク。

## 4. 確かめ方
1. 型チェックと単体テスト：`cd apps/note && npx tsc --noEmit && npx vitest run`（14項目）。サーバー側は `cd firebase/functions-note && npm run build`。
2. エミュレーターを動かす（`firebase/functions-note/.env.local` に `AI_FAKE=1`）。
   ```
   cd firebase/functions-note && npm run build
   cd apps/note && npx vite build
   cd firebase && firebase emulators:start --project demo-yado --only auth,firestore,functions,hosting,storage
   ```
   ローカルの `/api/contact` やAIの呼び出しを試すときは、プロキシの環境変数を外して起動する。
3. 読み書きの決まりのテスト：`cd firebase && node tests/note-rules.js`（36項目）。
4. 通しのテスト：`cd firebase && node tests/note-e2e.js`（28項目。CLAUDE.md の7章の3〜6と、管理者ページ）。`SHOTS=<フォルダ>` を付けると画面の写真を残す。
5. 旅館向けアプリのテスト（e2e.js、e2e-roles.js）も、同じエミュレーターで通る。
